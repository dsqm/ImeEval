# ImeEval — 输入法整句正确度评测

用模拟键盘测试闭源中文输入法（微软拼音 / 搜狗 / 百度等）的**整句转换正确率**。

程序向一个内嵌的文本框逐键发送真实按键，输入法正常参与转换，上屏后与期望文本比对，输出错字率、错句率、码长等指标。不依赖任何一家输入法的私有接口：只通过 Windows 公开的 IMM32 读取组字/上屏文本、控制 IME 开关状态，其余全部走真实键盘输入。

运行前提：Windows x64，需要 .NET 10 桌面运行时（程序是框架依赖的单文件）。

```
码表 + 测试文章 → 生成按键表 → 逐键模拟 → 上屏比对 → 错字率 / 错句率
```

---

## 快速开始（五步）

**第 0 步：让输入法模式与码表编码一致。**
码表里的按键串是什么方案，输入法就要切到什么模式——码表是小鹤双拼（如 `vs`=中、`go`=国、`vsgorfmbwjsv`=中国人民万岁），输入法就必须在小鹤双拼；否则输出会是乱码（如「脏欧能古偶」），那是模式不匹配，不是程序错。

1. **语料页**：把码表 `.txt` 放进 exe 旁的 **`\码表\`** 文件夹，把文章 `.txt` 放进 **`\文章\`**，分别在**下拉框**里选中；文章也可以在文本框里直接粘贴或修改。点「生成按键表」。
   - 码表没有的字符（OOV）**直接忽略排除**，不出清单、不计入统计分母；一字多码（多音字）自动取首码。
   - 生成成功后自动跳到「按键表」页。
2. **按键表页**：只读预览，每句一行（上方编码、下方字词），跑前人工核对一遍。点「跳转到运行」。
3. **速度标定页**：按键串默认 `mwlidevsgo_`（双拼「美丽的中国」+空格；全拼可填 `meilidezhongguo_`），期望上屏默认 `美丽的中国`，点「开始标定」。
   - 标定全程在**本页**进行：本页自带输入宿主，开始后不切页，可全程看着输入法组字上屏。
   - 标定会从快到慢找出这台机器 + 这个输入法的最快稳定间隔，推荐值（含容错）自动填入运行页「按键间隔ms」。
4. **运行页**：确认状态栏「前台=本窗口、宿主焦点=有」，点「▶ 开始」。
5. **看结果**：实时统计随时刷新（运行中带「预估剩余」），逐句对照在下方。

测试中随时可停：**F9** 全局热键、点「■ 停止 (F9)」，或切走窗口（运行页失焦自动停止；标定页失焦只暂停，60 秒不回来才中止）。

## 语料与码表

### 码表格式

每行一条映射，`#` 开头为注释，空行忽略：

```
中	vs
国	go
人	rf
民	mb
```

- 分隔符为 TAB 或一个或多个空格。
- 同一左列写多行 = 一字多码（多音字），生成时自动取首码，编译状态里会提示数量。
- 码表没有的字符（OOV）直接忽略排除：不出现在期望文本里，也不计入错字统计的分母。
- 下拉框只列 `\码表\` 里的 `.txt`；点「重新加载」刷新列表。码表加载后显示「N 字 + M 词组（最长 K 字）」。
- 文章下拉框同理；「打开文章文件夹」直接打开 `\文章\`。

### 词组（整词一次输入）

左列写 2 个及以上文本元素就是**词组**，生成按键表时**最长优先匹配**：命中就整词一次输入，不再逐字打。

```
# 多音字：取上方的那个（首码）
亲	qin
亲	qing
# 词组：优先级高于单字，"亲家" 整词一次输入
亲家	qingjia
```

- 优先级：逐位匹配，同一位置上是 **标点按键配置 > 词组（最长优先）> 单字**。勾掉「词组优先」即可只走单字，方便 A/B 对比。
  词组本身含标点时整词一次输入，不再走标点顶屏；但以标点开头的词组仍会先命中标点配置。
- 匹配只在**文本元素边界**上进行：高低代理对（emoji、扩展区汉字）与组合字符是一个整体，不会被从中间切开，也不会因为共用高位代理而被误判成另一个字。
- 词组不跨行（换行是上屏单元边界）。

### 标点按键配置

点「设置标点按键…」可自定义每个标点的输入键（与码表分开维护），默认内置 17 条常见中文标点：

```
。    .
，    ,
、    \
；    ;
：    <Shift+;>
？    <Shift+/>
！    <Shift+1>
……    <Shift+6>      ← 一次按键产出两字，左列写全
——    <Shift+->      ← 同上
```

每行一条：`标点 + 空格/制表符 + 按键串`，`#` 开头为注释，配置随方案保存在 `data\settings.json`。

- 左列允许**多个字符**（`……`、`——` 这类一次按键出两字的情况），匹配时取最长。
- 默认只收中文标点，不含英文标点（`. , ! ? ; :`），避免把英文句子里的句点误判成断句。
- 表里没有的字符一律转去查码表；码表也没有就当 OOV 直接过滤掉——**把这张表清空也只是退化为「统一走码表」，不会出错**。
- 改完点「确定」保存；「重置」恢复内置默认；有无效行会弹提示。

## 按键串语法

码表按键列、上屏键、标定按键串共用同一套语法：

| 写法 | 含义 |
|---|---|
| `zhong` | 普通字符，逐键发送 |
| `_` | **空格**（按键串里真实的空格、制表符会被直接忽略，当作不存在） |
| `<Shift+1>` | **组合键**：按住 Shift 敲 1（打出 `!`）。修饰键可用 Shift/Ctrl/Alt/Win，可叠加（如 `<Ctrl+Alt+A>`） |
| `<Shift>` | 特殊键，支持：`<Enter>`/`<Return>`/`<回车>`、`<Backspace>`/`<BS>`/`<退格>`、`<Esc>`/`<Escape>`、`<Tab>`/`<制表>`、`<Space>`/`<空格>`、`<Del>`/`<Delete>`/`<删除>`、`<Ins>`/`<Insert>`/`<插入>`、`<Home>`、`<End>`、`<PageUp>`/`<PgUp>`/`<上翻>`、`<PageDown>`/`<PgDn>`/`<下翻>`、`<Up>` `<Down>` `<Left>` `<Right>`（也认 `↑ ↓ ← →`）、`<Ctrl>`/`<Control>`、`<Alt>`、`<Win>`/`<Windows>`、`<CapsLock>`/`<Caps>`、`<NumLock>`、`<ScrollLock>`、`<PrintScreen>`/`<Prtsc>`、`<Pause>`、`<Menu>`/`<Apps>`、`<Numpad0>`、`<F1>`～`<F24>` |
| `{DELAY=100}` | 发到这里**等待 100 毫秒**再继续 |

示例：`zhong_`（打 zhong 后按空格）、`ni<Backspace>{DELAY=50}hao_`。

- 按键串在**发送时**才解析：无法识别的按键名/指令不会中断测试，运行结束时在日志里汇总本轮警告。
- 未闭合的 `<` 或 `{` 会丢弃该片段及其后的剩余部分。

## 编译选项

| 选项 | 默认 | 含义 |
|---|---|---|
| 单句上限 | 20（1～500） | 一个上屏单元最多多少**字**（代理对如 emoji/生僻字算 1 字）。命中词组时整词照常输入，单元可能超过上限 |
| 句尾等待ms | 0（0～5000） | 每句结尾、上屏键（或标点）之前插入 `{DELAY=n}`；0 = 不加 |
| 上屏键 | `_` | 每句结尾追加的确认按键；留空会回退为 `_` |
| 根据标点断句 | 开 | 在标点处结束这一句；**连续标点（如 `！？`）算同一句**。标点自己顶屏，句尾不再补上屏键 |
| 词组优先 | 开 | 码表词组整词一次输入（最长优先），关掉则只走单字 |

上次选中的码表/文章、全部编译选项与标点配置、窗口大小、运行参数、标定参数都会自动记忆在 `data\settings.json`（关闭窗口时保存）。

## 速度标定

- 每个输入法（甚至每台机器）的最快稳定速度不同：太快会丢键或失真，间隔不能写死，必须现场标定。
- 参数：按键串（默认 `mwlidevsgo_`）、期望上屏（默认 `美丽的中国`）、每组重复（默认 20，3～200）、容错+ms（默认 1，0～20）。
- 档位阶梯共 15 档：`0, 1, 2, 3, 4, 6, 8, 12, 16, 24, 32, 48, 64, 96, 128` ms。从快到慢，每档重复 N 组**全部正确**才算通过，命中即停；组间静默 200ms，避免上一组按键残留在 IME 管道里串进下一组。
- 推荐间隔**必须实测通过**才采用：从「最快档 + 容错」起逐 +1ms 验证（最多 6 档），取第一个完整档位通过的值；都不过则退回已验证的最快档。实测存在「0ms 全对、1ms 反而失真」的输入法（对特定间隔敏感），所以容错不能盲加。
- 结果栏显示「最快稳定间隔=Xms，推荐=Yms（已实测验证）」，推荐值自动填入运行页「按键间隔ms」，可随时手改。
- **上屏判定**：文本连续 40ms 不变、且输入法组字已结束，才认为本组上屏完成——组字中的拼音串不会被当成上屏文本误判失真。
- **焦点与前台**：每组发送前校验键盘焦点在标定宿主，不在则暂停发送并等待回归（最长 60 秒，期间可 F9 停止），超时中止；组内前台被抢会丢弃半组，等恢复后整组重发。发送过程中每个键校验前台窗口仍是本程序（不逐键校验控件焦点）。
- **IME 状态**：每组发送前检查 IME 是否被关闭（英文状态），被关闭会自动重开；IME 仍打开但输入模式是英文时，程序不会替你切换。
- **中止条件**：某档一组都没跑对、且此前从未有过正确输出，立即中止（通常是没切中文、方案不匹配或焦点不在宿主），继续扫下去没有意义。
- 标定期间请停留在本页，不要切换页签或点击其他窗口。

## 运行与停止

- 参数：按键间隔ms（默认 2，0～500）、静默期ms（默认 40，0～3000，上屏后文本连续多少毫秒不变即认为本句结束）、只看错误（默认勾选，逐句对照只显示错句）。
- 点「▶ 开始」后程序会把窗口抢到前台、焦点交给运行宿主（最多重试约 5 秒）；抢不到会在日志里警告。
- 停止来源：**F9** 全局热键、「■ 停止 (F9)」、主窗口失去焦点、键盘焦点离开宿主（如切换页签，逐句开始前校验）。
- **自动上屏**：发上屏键之前，若输入法已把整句高置信度上屏，程序会跳过这个上屏键，避免多打一个空格污染比对；运行中在按键表页该句句尾标绿 `⏎`，结束时日志给出句数。
- **IME 被切走**：每句开始前检查 IME 是否被关闭（英文状态），被关闭会自动重开，结束日志给出次数；IME 仍打开但处于英文模式时不会处理。
- **状态栏**五项：`SendInput 40B OK`、`前台 本窗口/其他`、`宿主焦点 有/无`、`热键 已注册/失败`、`间隔 Nms`；最新一条日志会短暂占用状态栏。
- 完整日志写入 `data\session.log`。

### 断点

- 每 20 个上屏单元自动写入 `data\checkpoint.json`，停止/结束时再兜底写一次；崩溃最多丢失最近 19 个单元的结果。
- 断点文件里保存了累计统计和当时的按键表，恢复不依赖当前语料。
- 点「↻ 从断点继续」从下一个单元的首键重打；若停止时当前单元只发了半句，该单元不计入结果，恢复时整句重来。
- 「出错」不会触发停止，也不会单独设断点——错句照常跑完。

## 结果与统计口径

实时统计随运行刷新：上屏句数、IME 实际提交、错句数/错句率、期望字数、错字数/错字率、准确率、替换/删除/插入、自然句错句率、码长、耗时、句/秒；运行中还会附「预估剩余：约 X（剩 N 句）」。

逐句对照每句一组条目：`✓/✗ 替S 删D 插I  XXms  上屏N  码长x.xx（N键/N字） [自动上屏]`，随后是按键串、期望、实际（错处用 `[...]` 标出并标红）和上屏分段（输入法每次提交的文本段）。

口径定义：

- **错字数 = 编辑距离**（Levenshtein），细分替换 / 删除 / 插入。
- **错字率 = 错字数 ÷ 期望总字数**；分母按 UTF-16 码元计，emoji、扩展区汉字等代理对算 2。
- **错句率 = 错句数 ÷ 上屏次数**（每个上屏单元独立比对、独立清空宿主，错误不跨单元传播）。
- **自然句错句率**：只在期望段以 `。！？!?…` 结尾时结算——累计到该终结符的错都算这一句；逗号、分号等不切自然句，文末没有终结符的尾句也不计入。
- **码长 = 按键数 ÷ 期望字数**：按键数含上屏键、不含 `{DELAY=}`；输入法自动上屏、上屏键被跳过时那个键不计。字数按文本元素口径，代理对算 1 字（与错字率分母不同）。
- **IME 实际提交**：输入法真正提交文本的事件数（GCS_RESULTSTR 次数；一字一屏会远大于句数）。运行中每 0.5 秒刷新一次（显示当前句的提交次数），结束汇总里才是全程累计。
- **句/秒** = 上屏次数 ÷ 各句耗时之和。

## 数据与便携化

程序产生的所有数据都在 **exe 文件夹**下，不写注册表、不写 C 盘用户目录：

```
ImeEval.exe
码表\                码表 .txt（下拉框选中即载入）
文章\                测试文章 .txt（下拉框选中即载入）
data\
├── settings.json    记忆的方案与参数
├── checkpoint.json  断点（累计统计 + 按键表快照）
├── session.log      运行日志（每次启动后追加）
└── smoke.log        --smoke 的输出（仅 --smoke 生成）
```

便携：整个文件夹拷走即可，方案与断点跟着走。

## 命令行

```
ImeEval.exe                          正常启动 GUI
ImeEval.exe --smoke <码表> <文章> [间隔ms]
                                      自动跑一轮：生成按键表 →（省略间隔时先标定）→ 运行
                                      窗口仍会显示；日志写 data\smoke.log
                                      退出码：0 跑完 / 1 未跑完 / 2 按键表为空 / 3 异常
                                      标定没找到可用档位时仍按当前间隔继续，只在日志里警告
ImeEval.exe --compile <码表> <文章> [句尾延迟ms]
                                      只做切分并打印每句按键串（无 UI、不碰焦点）
                                      句尾延迟默认 100ms；不读 data\settings.json，
                                      使用内置默认标点配置/上屏键/单句上限/词组优先
ImeEval.exe --poc [--auto]           技术验证窗口（--auto 自动跑四组；Ctrl+Alt+S 停止；
                                      日志写 poc-log.txt）
```

参数名大小写不敏感；参数不完整时会静默回落到正常 GUI。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 上屏全是乱码（如「脏欧能古偶」） | 输入法模式与码表编码不匹配（码表是双拼、输入法在全拼，或反之），切成一致 |
| 一个键都没进去 | 窗口不在前台或焦点不在宿主——看状态栏两项是否正常，把窗口点到最前面再开始 |
| 结果里混着没转换的拼音字母 | 同上，焦点丢了；程序已内置自动抢焦点，若仍出现请勿在测试期间点击其他窗口 |
| 丢字 / 整段丢失 | 间隔太快，回标定页重新标定 |
| 标定第一档就中止、输出全空 | 通常是输入法没切到中文（或与按键串方案不一致），或焦点不在标定宿主 |
| 第二遍跑正确率变高 | 输入法学习了你的语料（动态调频/用户词典）。多轮对比请换语料，或交叉顺序跑取平均 |
| 状态栏 SendInput 不是 40B OK | 当前构建是 win-x64，40B 是正常值；显示「错误!」说明二进制与输入结构体不匹配，换正确的构建而不是重启 |

## 架构与目录

分四层：UI（四个页签、全局热键与失焦入口）→ Core（Control：`RunController` 统一停止入口 + `Runner` 执行编排；Sending：`KeySeq` 按键串解析、`KeyPlayer` 发送、`Pacer` 定时、`Calibrator` 标定；Verify：`IUpTextSink` 上屏捕获抽象、`Verifier` 比对、Levenshtein/BenchStats 统计；Corpus：码表、文章编译、按键表、标点配置）→ Win32（SendInput、RichEdit 宿主与 IMM32 观测）。

发送循环跑在后台线程（Stopwatch 精确定时），UI 线程保持泵消息。层间依赖不是严格单向：验证层只依赖 `IUpTextSink`，由 Win32 的 `ImeHost` 实现；发送与标定层则直接调用 Win32 的 `InputSender`。

目录结构：

```
ImeEval/
├── samples/            示例码表与文章
├── Win32/              SendInput / 输入宿主 / IMM32 封装
├── Core/
│   ├── Control/        停止总控 + 执行编排
│   ├── Sending/        按键串 / 发送 / 定时 / 标定
│   ├── Verify/         上屏捕获抽象 + 比对统计
```
