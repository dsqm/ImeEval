# ImeBench — 输入法整句正确度评测

用模拟键盘测试闭源中文输入法（微软拼音 / 搜狗 / 百度等）的**整句转换正确率**。

程序向一个内嵌的文本框逐键发送真实按键，输入法正常参与转换，上屏后与期望文本比对，输出错字率与错句率。纯黑盒，不连任何输入法内部接口。

```
码表 + 测试文章 → 编译成按键表 → 逐键模拟 → 上屏比对 → 错字率 / 错句率
```

---

## 快速开始（五步）

**第 0 步：让输入法模式与码表编码一致。**
码表里的按键串是什么方案，输入法就要切到什么模式——码表是小鹤双拼（如 `vs`=中、`go`=国，`vsgorfmbwjsv`=中国人民万岁），输入法就必须在小鹤双拼；否则输出会是乱码（如「脏欧能古偶」），那是模式不匹配，不是程序错。

1. **语料页**：把码表 `.txt` 放进 exe 旁的 **`\码表\`** 文件夹，把文章 `.txt` 放进 **`\文章\`**，分别在**下拉框**里选中，点「编译 →」。
   - 码表没有的字符（OOV）**直接忽略排除**，不出清单、不计入统计分母；一字多码（多音字）自动取首码。
2. **速度标定页**：按键串填 `vsgo_`（小鹤双拼「中国」+空格；全拼则是 `zhongguo_`），期望上屏填 `中国`，点「开始标定」。
   - 标定会从快到慢找出这台机器 + 这个输入法的最快稳定间隔，推荐值（含容错）自动填入运行页。
3. **运行页**：确认状态栏全部正常（前台=本窗口、宿主焦点=有），点「▶ 开始」。
4. 测试中随时可停：**F9** 全局热键，或点「■ 停止 (F9)」，或直接切走窗口（失焦自动停止）。
5. 跑完在「实时统计」看汇总，逐句明细在下方「逐句对照」。

## 码表格式

每行一条映射，`#` 开头为注释：

```
中	zhong
国	guo
人	ren
，	,
```

- 分隔符为 TAB 或一个或多个空格（不再强制 TAB）。
- **同一左列写多行 = 一字多码**（多音字）。编译时自动取首码，状态栏会提示数量。
- 码表没有的字符（OOV）**直接忽略排除**：不出现在期望文本里，也不计入错字统计的分母。

### 词组（整词一次输入）

左列写 2 个字及以上就是**词组**，编译时**最长优先匹配**：命中就整词一次输入，不再逐字打。

```
# 多音字：取上方的那个（首码）
亲	qin
亲	qing
# 词组：优先级高于单字，"亲家" 整词一次输入
亲家	qingjia
```

- 优先级：逐位匹配，同一位置上是 **标点按键配置 > 词组（最长优先）> 单字**。语料页勾掉「词组优先」即可只走单字，方便 A/B 对比。
  词组本身含标点时（如整词里带句号）整词一次输入，此时不再走标点顶屏。
- 匹配只在**文本元素边界**上进行：高低代理对（emoji、扩展区汉字）与组合字符是一个整体，不会被从中间切开，也不会因为共用高位代理而被误判成另一个字。
- 词组不跨行（换行是上屏单元边界）。

## 按键串语法

码表按键列、确认键、分隔符、标定按键串共用同一套语法：

| 写法 | 含义 |
|---|---|
| `zhong` | 普通字符，逐键发送 |
| `_` | **空格**（按键串里真实的空格字符会被直接忽略，当作不存在） |
| `<Shift+1>` | **组合键**：按住 Shift 敲 1（打出 `!`）。单点修饰键仍写 `<Shift>`，两者语义不冲突 |
| `<Shift>` | 特殊键。支持：`<Enter>` 回车、`<Backspace>`/`<BS>` 退格、`<Esc>`、`<Tab>`、`<Del>`/`<Delete>`、`<Ins>`、`<Home>`、`<End>`、`<PageUp>`/`<PageDown>`、`<Up>` `<Down>` `<Left>` `<Right>` 方向键、`<Shift>` `<Ctrl>` `<Alt>` `<Win>` 修饰键、`<CapsLock>`、`<NumLock>`、`<PrintScreen>`、`<Pause>`、`<F1>`~`<F24>`；也支持中文别名 `<回车>` `<退格>` `<空格>` `<删除>` `<插入>` `<上翻>` `<下翻>` |
| `{DELAY=100}` | 发到这里**等待 100 毫秒**再继续 |

示例：`zhong_`（打 zhong 后按空格）、`ni<Backspace>{DELAY=50}hao_`。

无法识别的按键名 / 指令会在编译时和运行日志里给出警告并跳过，不会中断测试。

## 编译选项

| 选项 | 含义 |
|---|---|
| 单句上限 | 一个上屏单元最多多少**字**（默认 20；代理对字符如 emoji/生僻字算 1 字），超过就分段上屏 |
| 句尾等待ms | 每句结尾、上屏键之前插入 `{DELAY=n}`；0 = 不加。标点收尾同样生效（如 `zhongguo{DELAY=100},`） |
| 上屏键 | 每句结尾追加的确认按键，默认 `_`（空格） |
| 根据标点断句 | 在标点处结束这一句；**连续标点（如 `！？`）算同一句**。标点自己顶屏，句尾不再补上屏键 |
| 词组优先 | 码表左列 ≥2 字的条目整词一次输入（最长优先），勾掉则只走单字 |

### 标点按键配置

点「设置标点按键…」可自定义每个标点的输入键（与码表分开维护），默认已内置常见中文标点：

```
。    .
，    ,
！    <Shift+1>
？    <Shift+/>
：    <Shift+;>
……    <Shift+6>      ← 一次按键产出两字，左列写全
——    <Shift+->      ← 同上
【    <Shift+[>
```

每行一条：`标点 + 空格/制表符 + 按键串`，`#` 开头为注释，配置随方案保存在 `data\settings.json`。

- 左列允许**多个字符**（`……`、`——` 这类一次按键出两字的情况），匹配时取最长。
- 只收中文标点：默认**不含**英文标点（`. , ! ? ; :`），避免把英文句子里的句点误判成断句。
- 表里没有的字符一律转去查码表；码表也没有就当 OOV 直接过滤掉——**把这张表清空也只是退化为「统一走码表」，不会出错**。

上次选中的文章和全部编译选项会自动记忆（`data\settings.json`），下次打开还是上次的方案。

## 便携化

程序产生的所有数据都在 **exe 文件夹**下，不写注册表、不写 C 盘用户目录：

```
ImeBench.exe
码表\                码表 .txt（下拉框选中即载入）
文章\                测试文章 .txt（语料页下拉框选中即载入）
data\
├── settings.json    记忆的方案（码表/文章选择 + 编译选项）
└── checkpoint.json  断点
```

## 按键表页

编译产物是一张**可编辑的按键表**（一行 = 一个上屏单元）。这一页的网格里有两个**显示符号**（仅用于展示，不是按键串语法）：`⏎` = 确认上屏，`␣` = 音节分隔符。改完直接生效；也可保存 / 载入 `.ikeys.json` 复用。

## 速度标定怎么做

- 每个输入法（甚至每台机器）的最快稳定速度不同：太快会丢键或失真。
- 标定按 `0→1→2→…→128ms` 从快到慢扫，每档重复 N 组**全部正确**才算通过，命中即停。
- 结果 + 容错（默认 1ms）= 推荐间隔，自动填入运行页「按键间隔」，可随时手改。
- 若某档一个输出都没有会立即中止——先检查：是否切到全拼？窗口是否在前台、焦点是否在宿主？

## 停止与断点

- **F9**：全局热键，任何时候可停。
- **主窗口失焦即停**：测试期间切换窗口会自动停止。
- **句级断点 + 句首重入**：停止/崩溃后重开程序，点「↻ 从断点继续」，从出错那句的**句首**重打（半句丢弃，保证每句测量条件一致）。
- 自动检查点定期落盘到 exe 文件夹 `data\checkpoint.json`。

## 统计口径

- **错字数 = 编辑距离**（Levenshtein），细分：替换 / 删除 / 插入。
- 错字率 = 错字数 ÷ 期望总字数；错句率 = 错句数 ÷ 上屏次数（一次上屏与期望不完全一致即记 1 错句）。
- 每个上屏单元独立比对、独立清空，错误不跨句传播。
- 另有「自然句错句率」：按标点切分的自然句口径。
- **码长 = 按键数 ÷ 字数**（平均按键次数，键/字）。按键数含上屏键与音节分隔符，`{DELAY=}` 不算按键；输入法高置信度自动上屏、上屏键被跳过时那一个键也不计。字数按文本元素口径（代理对算 1 字）。

## 命令行

```
ImeBench.exe                          正常启动 GUI
ImeBench.exe --smoke <码表> <文章> [间隔ms]
                                      无人值守：编译→标定(省略间隔时)→跑完
                                      完整日志写入 exe 文件夹 data\smoke.log
ImeBench.exe --compile <码表> <文章> [句尾延迟ms]
                                      只做切分并打印每句按键串（无 UI、不碰焦点），
                                      用于后台调试语料切分
ImeBench.exe --poc                    打开底层技术验证窗口（排查问题时用）
```

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 上屏全是乱码（如「脏欧能古偶」） | 输入法模式与码表编码不匹配（码表是双拼、输入法在全拼，或反之），切成一致 |
| 一个键都没进去 | 窗口不在前台或焦点不在宿主——看状态栏两项是否正常，把窗口点到最前面再开始 |
| 结果里混着没转换的拼音字母 | 同上，焦点丢了；程序已内置自动抢焦点，若仍出现请勿在测试期间点击其他窗口 |
| 丢字 / 整段丢失 | 间隔太快，回标定页重新标定 |
| 第二遍跑正确率变高 | 输入法学习了你的语料（动态调频/用户词典）。多轮对比请换语料，或交叉顺序跑取平均 |
| 状态栏 SendInput 不是 40B OK | 程序异常，重启程序 |

## 架构分层

```
UI (UI/)                     界面、热键注册、失焦消息的入口
  │
  ├─ 控制层 Core/Control/     RunController：统一停止入口（热键/按钮/失焦）+ 每键闸门
  │                           Runner：编排层，把三层串成"发→收→比"的循环 + 断点落盘
  ├─ 发送层 Core/Sending/     KeyPlayer：读按键表逐键发送；Pacer：精确定时；Calibrator：速度标定
  ├─ 验证层 Core/Verify/      Verifier：捕获上屏文本并比对；Scoring：Levenshtein 比对与错字/错句统计
  └─ 语料层 Core/Corpus/      CodeTable：码表；Compiler：文章→按键表；KeyTable：可编辑按键表
  │
  └─ Win32/                  SendInput / 宿主控件(ImeHost) / Win32 P/Invoke
```

依赖方向自上而下：UI → 各层 → Win32。层与层之间不互相回调；验证层只依赖 `IUpTextSink` 接口，将来换 TSF sink 或外部窗口捕获时，上层无需改动。
